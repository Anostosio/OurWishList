# OurWishList — MVP

Статус: рабочая спецификация продукта  
Версия: 1.0  
Дата: 8 сентября 2026

## 1. Цель продукта

OurWishList — приватное Telegram Mini App для пары. Оно помогает сохранять желания, делиться ими с партнёром и выбирать подарки без лишних вопросов и случайных повторов.

Главная ценность MVP: пользователь отправляет ссылку на товар или заполняет желание вручную, получает аккуратную карточку, а партнёр сразу видит актуальный список.

## 2. Для кого продукт

- Два человека, связанные в одну приватную пару.
- Оба используют Telegram и открывают приложение через бота.
- Каждый управляет своими желаниями и видит желания партнёра.

В MVP одна пара состоит максимум из двух участников. Один пользователь может состоять только в одной активной паре.

## 3. Основные сценарии

### 3.1. Первый запуск

1. Пользователь открывает бота и запускает Mini App.
2. Если пары ещё нет, приложение предлагает создать приглашение.
3. Партнёр переходит по одноразовой ссылке и присоединяется.
4. После соединения оба видят четыре раздела: «Моё», «Партнёра», «Общее», «Сбылось».

### 3.2. Добавление желания по ссылке

1. Пользователь нажимает «Добавить».
2. Вставляет ссылку на товар.
3. Приложение пытается автоматически получить название, изображение и цену.
4. Пользователь проверяет данные, при необходимости редактирует их и сохраняет карточку.
5. Новая карточка сразу появляется в разделе «Моё» или «Общее».

Сбой автозаполнения не должен блокировать создание желания. Все поля можно заполнить вручную.

### 3.3. Добавление без ссылки

Пользователь может создать желание вручную: впечатление, поездку, услугу или товар без страницы магазина. К желанию можно добавить фотографию с устройства; перед отправкой она уменьшается до безопасного размера.

### 3.4. Просмотр списка

При открытии Mini App первой отображается галерея желаний. Фильтры не открываются автоматически. Пользователь переключается между разделами и открывает карточки без перехода обратно в чат.

### 3.5. Работа с желанием

Автор может изменить, архивировать или вернуть своё желание. Партнёр может открыть магазин и отметить, что собирается подарить желание. Автор не видит такую бронь.

## 4. Состав карточки

Обязательные данные:

- название;
- автор;
- принадлежность: личное или общее;
- приоритет;
- дата создания.

Дополнительные данные:

- ссылка на магазин;
- изображение;
- цена и валюта;
- дата проверки цены;
- категория;
- размер;
- цвет;
- комментарий;
- подходит ли аналог;
- статус «Сбылось»;
- скрытая от автора бронь партнёра.

Название обязательно. Остальные поля не должны мешать сохранению карточки.

## 5. Разделы приложения

- **Моё** — активные личные желания текущего пользователя.
- **Партнёра** — активные личные желания второго участника.
- **Общее** — желания для пары.
- **Сбылось** — архив выполненных желаний.

На пустом экране показываются утверждённые логотип и иллюстрация коробки, понятное сообщение и кнопка «Добавить желание».

## 6. Фильтры и сортировка

Фильтры доступны из отдельного меню и закрыты при первом открытии приложения.

MVP поддерживает:

- поиск по названию и комментарию;
- фильтр по категории;
- максимальный бюджет с валютой;
- порядок по приоритету;
- порядок по дате добавления;
- сброс фильтров.

## 7. Визуальные правила

- Основная палитра: белая и фисташковая.
- Тёмная тема: глубокий тёмно-зелёный фон, светлый текст, фисташковый акцент.
- Светлая тема: светлый фон, тёмный текст, тот же фисташковый акцент.
- Тема выбирается верхним переключателем и запоминается.
- Утверждённый логотип и иллюстрация пустого состояния не перерисовываются без отдельного согласования.
- Галерея — главный экран; элементы управления не должны заслонять карточки.
- Основные кнопки должны быть доступны большим пальцем на мобильном экране.
- Интерфейс проектируется прежде всего для ширины 360–480 px.
- Текст не обрезается и не выходит за границы при системном масштабе шрифта.
- В интерфейсе нет технических сообщений, URL API и внутренних идентификаторов.

## 8. Telegram-бот

Бот остаётся входной точкой и резервным интерфейсом. Он должен:

- открывать Mini App по команде `/app`;
- принимать ссылку на товар прямо в чате;
- создавать и принимать приглашение в пару;
- показывать базовые списки и карточки;
- сообщать понятную ошибку, если Mini App временно недоступен.

Основной пользовательский интерфейс развивается в Mini App.

## 9. Автозаполнение по ссылке

Система извлекает данные в таком порядке:

1. JSON-LD товара;
2. Open Graph;
3. стандартные метатеги страницы;
4. безопасные значения по умолчанию.

Требования:

- URL проверяется до сетевого запроса;
- запрещены локальные и внутренние сетевые адреса;
- запрос имеет ограничение времени и размера ответа;
- редиректы повторно проверяются;
- изображение и цена показываются пользователю до сохранения, если это возможно;
- пользователь всегда может исправить результат вручную;
- источник и дата последней проверки цены сохраняются.

## 10. Данные и приватность

- Production-данные хранятся в Postgres.
- SQLite используется только для локальной разработки и переноса данных.
- Mini App проверяет подписанные Telegram init data; временная сессия остаётся резервным способом входа через сообщение бота.
- API проверяет Telegram-подпись или резервную сессию на каждом запросе.
- Пользователь видит только данные своей пары.
- Бронь подарка скрыта от автора желания.
- Токены, строки подключения и секреты не хранятся в GitHub.
- В логах не выводятся токен бота, сессионные ключи и полные строки подключения.

## 11. Техническая основа

- Python 3.12+.
- Telegram Bot API.
- Статический Mini App: HTML, CSS и JavaScript без обязательного фронтенд-фреймворка.
- Vercel для production-фронтенда, API и webhook.
- Postgres для production-хранилища.
- GitHub `main` — источник production-развёртывания.
- Постоянный адрес Mini App: `https://ourwishlist-silk.vercel.app`.

## 13. Не входит в MVP

- публичные списки и социальная лента;
- группы больше двух человек;
- рекомендации на основе ИИ;
- сравнение цен между магазинами;
- автоматическая покупка или оплата;
- нативные приложения для iOS и Android;
- сложная система ролей;
- платная подписка;
- уведомления о снижении цены;
- локализация на несколько языков.

Эти функции обсуждаются только после выполнения критериев MVP.

## 14. Критерии готовности

MVP считается готовым, когда:

1. Два новых пользователя могут создать пару без ручного изменения базы.
2. Каждый может добавить желание вручную и по обычной ссылке магазина.
3. Карточка появляется у обоих пользователей не позднее следующего обновления списка.
4. Пользователь может изменить и архивировать своё желание.
5. Партнёр может скрытно забронировать подарок.
6. После перезапуска бота, нового развёртывания и повторного входа данные сохраняются.
7. Основные сценарии проходят в актуальных версиях Telegram на Android и iOS.
8. Страница production открывается без предупреждений стороннего туннеля.
9. В консоли браузера и журналах Vercel нет необработанных ошибок основного сценария.
10. Утверждённые визуальные материалы отображаются без размытия, обрезания и подмены.

## 15. Порядок дальнейшей работы в Goal

Каждая задача должна быть связана с пунктом этой спецификации. Работа выполняется в таком порядке:

1. Проверить текущее состояние production и воспроизвести проблему.
2. Выбрать один законченный пользовательский сценарий.
3. Реализовать его без удаления уже работающих функций.
4. Проверить интерфейс на мобильной ширине в светлой и тёмной теме.
5. Проверить связку Mini App → API → база данных.
6. Запустить относящиеся к изменению тесты.
7. Отправить изменение в GitHub `main`.
8. Дождаться статуса Vercel `Ready`.
9. Проверить постоянный production-адрес.
10. Отметить выполненные пункты в этом файле только после фактической проверки.

При конфликте между случайной реализацией и этим документом приоритет имеет `MVP.md`. Изменение продуктового поведения или визуального направления сначала фиксируется в этом файле.
